一台摄像机。
真实的运动数据。

CourtSense 把网球教练普通的训练视频变成每位球员的跑动距离、速度、场上位置和热力图。Meta SAM 3.1 负责追踪球员，Muse Spark 智能体回答教练的问题，并核对它给出的每一个数字。

▶ 观看 3 分钟演示 查看代码

问题

教练拍下每一次训练，然后却只能回看。

想知道一名球员跑了多远、多快、站在哪里，通常需要大多数俱乐部负担不起的追踪系统。我们的教练只有一台架在底线后方的摄像机。CourtSense 正是用它来工作。

工作原理

从教练的视频到以米为单位的球场

  1. 1

    上传训练

    教练选出视频中要分析的部分。一次 SAM 3.1 流式请求就能找到两位球员，并在每一帧中追踪他们。一次 12 分钟的训练有 10,688 帧，费用约 $2.14。

  2. 2

    点击球场上的四个点

    在单打边线的四个交点上点击四次，即可确定一个单应性变换。此后每一步都是球场上以米为单位的位置，从近端底线中点量起（单打场地宽 8.23 m，长 23.77 m）。

  3. 3

    查看数字

    跑动距离、平均和最高速度、在底线后、底线上、中场和网前的时间，左/中/右分布，以及每位球员的热力图。测量较粗略时，数值会用 ~ 标出，而不是显得很精确，各区域占比也会给出范围。

  4. 4

    问教练助手

    Muse Spark 智能体自己选择工具，把视频跳到它正在谈论的时刻，还能亲自观看那段片段。教练可以打字提问，也可以直接说出来。回答中的每一个数字都会在教练看到之前与数据核对，教练报告中的每个数字也一样。

  5. 5

    获取报告

    每次训练结束后，Muse Spark 只用测得的数字写一份简短报告，语言为英语或土耳其语（我们教练的语言）。

教练助手的内部

它会展示推理过程，也无法编造数字

Where did Player A run fastest? Show me that moment and describe what happens.

  1. Looking for moments: fastest moments (Player A)
  2. Jumping the video to 6:44
  3. ▶ 6:44 · Player A fastest run
  4. Watching 5 s from 6:44
  5. Reading the metrics (Player A)
  6. Checking the answer

Player A's fastest 1-s run was at 6:44 at 3.81 m/s.

✓ Verified · 5 steps · ~$0.019

这是在应用中录下的一次真实运行。智能体每轮只调用一个工具，最多八轮：

  • get_metrics每位球员的训练指标，附可靠性说明
  • find_moments最快的冲刺、最长的跑动和上网次数，按视频时间
  • minute_breakdown每分钟米数
  • show_moment把教练的视频跳到某个时间点
  • look_at_clip截取 2–8 秒并询问 Muse Spark 发生了什么
  • answer最终回答：每个数字都作为一条声明列出并与训练数据核对，否则退回给模型

内置 Meta AI

每个 Meta 模型在这里做什么

Meta 模型或软件包在 CourtSense 中的作用
SAM 3.1根据文本提示 "tennis player"，在训练的每一帧中找到并追踪两位球员，只需通过 Meta Model API 发出一次流式请求。
Muse Spark 1.3运行教练助手：选择工具，通过视频输入观看短片段，用英语或土耳其语回答。也负责撰写教练报告。
Muse Voice Transcribe让教练用英语或土耳其语语音向助手提问。识别出的文字会出现在提问框中，提问前可以先检查。
@meta-sam/parser把 SAM 3.1 的流式输出读取为每一帧的边框和遮罩。
@meta-sam/react, @meta-sam/graphics在浏览器中播放训练，并用各自的颜色画出每位球员的遮罩。

为一位真实的教练打造

用我们教练自己的训练打造

我把我们所有的训练都拍下来，但直到现在都只能回看。有了 CourtSense，我能用数字看到球员跑了多远、在场上站在哪里。从现在起，我会根据这些数据来安排训练。

我们的教练，在一条语音消息中（译自土耳其语）。训练由我们的教练拍摄，并征得了两位球员的同意。

不是泛泛的运动分析工具。它为我们自己的教练打造，核心是 SAM 3.1。

坦诚的局限

它目前还做不到的

  • 没有网球追踪

    在我们的画面中，SAM 3.1 会把天花板灯和标牌误认成网球，所以目前还没有击球或比分统计。

  • 远端深度较粗略

    摄像机位置较低时，远端球员的前后位置是粗略的：在人工标注的帧上误差约 1 m。应用会标明这一点，并给出区域范围，而不是靠猜。左右位置依然可靠。

  • 摄像机漂移

    长时间训练中摄像机云台的缓慢漂移目前还没有补偿。
